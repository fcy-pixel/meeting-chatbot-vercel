# 校務會議紀錄查詢

以學校會議紀錄作知識庫，直接提問、整理重點及連續追問。AI 根據所選學年的文件回答，並提供可點擊的來源。

## 文件聊天

保留一般聊天和連續追問，加入類似 NotebookLM 的核心文件問答流程：先勾選來源，再讓 AI 綜合整理，點擊引用核對原文，然後繼續追問。

- 來源清單可按檔名搜尋、勾選及閱讀。每次查詢只讀取該學年本次勾選的文件；沒有勾選來源便不能發送。改變來源時取消未完成回覆，已完成的同學年對話仍可用來理解追問。
- 可要求條列、簡短解釋或比較表格，也可選擇簡短／適中／詳細。一鍵整理文件重點、重要日期和會議差異；回答後可再要求縮短、重點或表格。
- 答案以安全 Markdown 顯示，不執行原始 HTML，不採用模型提供的連結或圖片。每段引用編號可打開右側原文，顯示精確摘錄、該頁完整文字及原 PDF。
- 原文閱讀器 `/api/source-text` 固定在回答當時的 Git commit，逐頁核對 PDF 與抽取文字版本；頁面沒有文字長度截斷。可翻頁查看前後文。
- 可停止回覆、開始新對話；輸入框以 Enter 發送、Shift + Enter 換行。

## 文件與上載

- 管理員上載時，由伺服器使用 unpdf 抽取每一頁的文字，不使用 OCR。無效 PDF、任何一頁沒有可用文字、或明示學年與所選學年不同，都會在寫入前拒絕。
- 每份 PDF、完整 `.txt` 和逐頁 `.json` 在同一次 Git commit 保存；使用非強制 ref 更新，遇到並行修改便回報失敗，避免半份文件被採用。
- JSON 包含原始檔名、學年、PDF 路徑、SHA-256、Git blob SHA、實際頁數和逐頁原文。引用頁碼由 PDF 第 1 頁起計，並非頁面印刷頁碼。
- 舊版純文字檔不能提供可靠頁碼，必須由原 PDF 重新抽取。`npm run extract` 用相同抽取器處理 `pdfs/<學年>/*.pdf`。
- 每份上限 20 MB；超過便明確拒絕，請先按會議拆分。空白頁亦會拒絕，請管理員提供每頁均含文字的版本。

## 回答與引用

`/api/chat` 從 GitHub 的同一 commit 讀取所選文件，不把瀏覽器傳入的文件或舊助手答案當作事實依據。PDF blob SHA 與 JSON 必須相符。未分類或無法讀取的文件會顯示為未完成項目。

一般問題先從預先抽取的全文找相關頁面，再由 AI 整理回答。取消逐句語意覆核、日期字眼攔截及「未通過覆核就拒答」流程。有部分資料便先回答，文件沒寫清楚的事項直接說明；完全找不到相關資料才回覆沒有找到。提示要求不編造人名、日期、金額或安排，保留暫定條件及新舊說法的差異。這是來源輔助問答，沒有另一輪模型審批答案，也不保證 AI 每次理解都正確；老師可點擊引用核對。

上載時已抽取並保存逐頁文字；提問不再讀取 PDF 或重新抽字。伺服器以關鍵字在所選文件的全部文字中搜尋，優先相關頁面及相鄰頁的表格內容，通常只送出最多約 18,000 字元的來源資料。此搜尋不呼叫 Qwen，也沒有另外的向量模型費用。

全年摘要、整理全部文件、較小的來源集合或沒有關鍵字匹配時，仍使用全文。若首次相關段落未能回答（模型回傳空 claims），會自動讀取其餘文字一次；資料依 140,000 字元分批，不會因查找不到便要求使用者重新提問。提示要求有限段落不足以回答時交由系統擴大搜尋，不聲稱整份文件沒有答案。關鍵字搜尋仍可能漏掉同義表達，因此保留擴大搜尋及全文模式。

原文從不截短；畫面分開顯示全文搜尋範圍和 AI 實際參考頁次，展開可看精確字元範圍、所用來源字元數及 API 回傳的輸入／輸出 token 用量（包含追問理解及有用量回傳的重試）。字元數是去除重複送入後的來源大小，並非計費 token。部分批次連線失敗時，仍顯示其他批次的答案及未完成部分。只有讀完全文且沒有相關答案才回報全範圍的 `not_found`。

引用只可指向本次提供的來源。檔名、學年及實體 PDF 頁碼由程式對應；摘錄須是原文字串。如果模型抄錄不一致，改顯示該頁的實際原文段落；找不到有效來源 id 時保留答案並提示未能定位頁碼，絕不製造來源。引用檢查不再阻擋整段回答。

聊天支援「那交給誰？」、「3月份有改嗎？」和「簡短一點」。先把追問理解成完整查詢，再查閱可信文件；歷史答案只用來識別話題。一般招呼及道謝直接回應。切換學年會取消原請求並清除對話。「新對話」可重設；超過 60,000 字或 200 則對話會明確請使用者開始新對話，不靜默捨棄上文。

## 模型

一般文件問答直接使用 `qwen3-max`；需要承接上文時，先用 `qwen-plus` 釐清問題。均關閉思考模式並要求 JSON 回應。只有不完整的答案結構會重試一次，不再另外呼叫模型覆核內容。

## 開發與驗收

- `npm test`：資料保存、超長文件尾段、可靠引用、學年、失敗處理及 API 路由測試。
- `npx tsc --noEmit`：型別檢查。
- `npm run pages:build`：Cloudflare Pages 建置。
- `npm run test:acceptance -- --endpoint`：以 `tests/fixtures/acceptance.json` 的實際問題和標準答案測試網站。可用 `EVAL_BASE_URL` 指定驗證網址。
- `npm run test:conversation`：用實際逐輪回答測試追問、簡短整理、轉話題、跨會議比較、學年隔離、沒有答案及錯誤歷史答案；亦支援 `EVAL_BASE_URL`。
- `npm run test:notebook`：逐輪測試所選來源的整理、縮短、表格、無答案追問、跨會議比較，以及單份和全年重點整理。驗證實際渲染的表格、逐字引文及來源閱讀器。可用 `EVAL_REPORT_NAME` 保存不同輪次紀錄。
- `npm run test:acceptance -- --endpoint --notebook`：用新版來源選擇協定重測原有 8 題標準答案。
- `QWEN_API_KEY=... npm run test:acceptance`：直接驗證同一模型回答流程。金鑰只放在本機環境變數，不提交。

驗收包括人名、內文與檔名日期差異、新舊學年同類事項、跨會議改動、同文件矛盾和沒有答案的問題。程式核對狀態、必要答案、來源頁次、所有摘錄與原文是否一致，以及查閱範圍是否完整；結果仍需閱讀完整回答核對語意。

Cloudflare 原有 `QWEN_API_KEY`、`GITHUB_TOKEN`、`GITHUB_REPO`、`ADMIN_PASSWORD` 環境變數不變。登入所用 `NEXT_PUBLIC_GOOGLE_CLIENT_ID` 必須在建置時設定。
